## The dispatch floor, at last measured

`noop` sends NoOperation requests and nothing else: **26.7 us per request**.

That retires a claim this branch made twice on indirect evidence. Text runs
at 45.7 us per character, and a `PolyText8` carries 54 of them, so a text
request is 2.97 ms of which dispatch is 0.027 -- **one per cent**. The
earlier reasoning compared a per-character time against a per-request cost
and concluded the protocol was eating the difference. It is not. Text is
bounded by writing pixels to VRAM, which is where a glyph blitter should
be, and there is nothing further to win there without writing pairs.

## PutImage: transport after all, and the number now supports it

49 ops/s over 10100 pixels is 2.02 us per pixel, against 0.41 the board
takes for 32-bit stores. With dispatch measured at 27 us -- 0.13% of a
20 ms request -- the remaining 1.6 us per pixel is moving 20 KB through the
socket, about 1 MB/s.

So the earlier correction was itself half wrong. MIT-SHM removes the
transport, which is 80% of what is left; the memcpy fix removed 1.05 us per
pixel of the drawing. Both mattered, and the saku26 project's estimate was
closer than the rebuttal.

## A server bug found by accident

A burst of 20000 four-byte NoOperation requests makes the server drop the
client a few thousand requests later:

    XIO: fatal IO error 32 (Broken pipe) on X server ":0.0"
         after 23091 requests (20014 known processed)

It reproduces. Whether it is the X11R4 Xlib on this machine or the server's
input handling is unknown, and it may or may not have anything to do with
the desktop stalls. `noop` runs last in the benchmark so the rest survives.
